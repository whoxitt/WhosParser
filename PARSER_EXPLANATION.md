# 🔍 Как работает парсер по чатам

## 📖 Общее описание

Парсер NFT подарков - это система, которая автоматически проверяет участников ваших Telegram чатов и групп на наличие NFT подарков.

---

## 🔄 Процесс работы парсера (пошагово)

### Этап 1: Подключение аккаунта

```
Пользователь → Бот → Telethon → Telegram API
     ↓
Ввод номера телефона
     ↓
Получение кода подтверждения
     ↓
Ввод кода через пробелы: "1 2 3 4 5"
     ↓
Создание StringSession
     ↓
Сохранение в PostgreSQL базу
```

**Что происходит:**
1. Бот создаёт Telethon клиент (MTProto API)
2. Отправляет запрос авторизации на ваш номер
3. Telegram присылает код подтверждения
4. После ввода кода создаётся авторизованная сессия
5. Сессия сохраняется как строка (StringSession) в базу данных
6. При перезапуске бота сессия восстанавливается автоматически

---

### Этап 2: Загрузка списка чатов

```
Telethon клиент → iter_dialogs() → Telegram API
         ↓
Получение всех диалогов
         ↓
Фильтрация только групп и каналов
         ↓
Сохранение в таблицу parser_chats
```

**Что происходит:**
1. Через Telethon запрашивается список всех ваших диалогов
2. Отфильтровываются только группы и каналы (приватные чаты игнорируются)
3. Для каждого чата сохраняется:
   - ID чата
   - Название
   - Username (если есть)
   - Тип (группа/канал)
   - Количество участников
   - Статус (включён/выключен для парсинга)

---

### Этап 3: Выбор режима парсинга

Пользователь выбирает один из режимов:

#### 🎁 Режим "Любые NFT"
- Ищет всех пользователей с любыми NFT подарками
- Показывает обычные подарки, коллекционные и неулучшенные

#### 💎 Режим "Только неулучшенные"
- Ищет только подарки, которые можно улучшить
- Использует фильтр `exclude_unupgradable=True` на уровне API
- Экономит время - не загружает обычные подарки

---

### Этап 4: Парсинг участников

```
Для каждого включённого чата:
    ↓
iter_participants(chat_id) → Telegram API
    ↓
Получение списка участников (батчами по 100)
    ↓
Фильтрация (убираем ботов и удалённых)
    ↓
Проверка в базе (уже проверяли?)
    ↓
Добавление в очередь для проверки NFT
```

**Что происходит:**
1. Для каждого выбранного чата запрашивается список участников
2. Участники загружаются батчами (группами) по 100 человек
3. Исключаются:
   - Боты (is_bot=True)
   - Удалённые аккаунты (deleted=True)
   - Уже проверенные пользователи (есть в базе)
4. Каждый участник добавляется в очередь на проверку NFT

---

### Этап 5: Проверка NFT у пользователя

```
Для каждого пользователя:
    ↓
payments.GetSavedStarGiftsRequest(user_id) → Telegram MTProto API
    ↓
Получение списка подарков пользователя
    ↓
Применение фильтров (exclude_unupgradable=True для режима 💎)
    ↓
Парсинг данных о каждом подарке:
    - ID подарка
    - Название
    - Номер
    - Можно ли улучшить (can_upgrade)
    - Является ли коллекционным (is_collectible)
    ↓
Сохранение в таблицу parser_gifts
    ↓
Отправка карточки пользователю (если найден NFT)
```

**Что происходит:**
1. Через MTProto API отправляется запрос `payments.GetSavedStarGiftsRequest`
2. Это официальный Telegram API метод для получения подарков
3. Telegram возвращает список всех подарков пользователя
4. В режиме "неулучшенные" применяется фильтр на уровне API
5. Каждый подарок парсится и сохраняется в базу
6. Если у пользователя есть NFT - отправляется карточка администратору

## 🎯 Ключевые особенности

### 1. Паузы между запросами

```python
await asyncio.sleep(random.uniform(0.5, 1.5))  # Случайная пауза
```

**Зачем:**
- Telegram ограничивает скорость API запросов
- Без пауз получите FloodWaitError (блокировка на N секунд)
- Случайные паузы выглядят как действия человека

### 2. Обработка FloodWait

```python
try:
    gifts = await client.get_user_gifts(user_id)
except FloodWaitError as e:
    wait_seconds = e.seconds
    log.warning(f'FloodWait {wait_seconds}s, ждём...')
    await asyncio.sleep(wait_seconds)
    # Повторяем запрос
```

**Что происходит:**
- Telegram говорит "слишком много запросов, подожди N секунд"
- Бот автоматически ждёт указанное время
- Продолжает работу после ожидания

### 3. Дедупликация (без повторов)

```sql
-- В базе данных
UNIQUE(user_id, source_chat_id)  -- Один юзер из одного чата
UNIQUE(user_id, gift_id, gift_num)  -- Один подарок
```

**Зачем:**
- Один пользователь может быть в нескольких чатах
- Проверяем каждого только один раз
- Не дублируем подарки в базе

### 4. Батчинг (пакетная обработка)

```python
# Загружаем по 100 участников за раз
async for user in client.iter_participants(chat_id, limit=100):
    # Обрабатываем
```

**Зачем:**
- API не даёт загрузить всех сразу (в больших чатах 10000+ человек)
- Батчи позволяют обрабатывать большие группы
- Экономит память

## 📊 Схема базы данных

### Таблица `parser_session`
Хранит авторизованную сессию Telegram аккаунта:
```sql
- id: уникальный ID
- owner_id: Telegram ID владельца
- session_string: StringSession (зашифрованная сессия)
- phone: номер телефона
- username: @username
- user_id: Telegram user ID
- is_active: активна ли сессия
```

### Таблица `parser_chats`
Список всех ваших чатов:
```sql
- chat_id: ID чата
- title: название чата
- username: @username чата (если публичный)
- chat_type: 'group' или 'channel'
- participants_count: количество участников
- is_enabled: включён ли для парсинга
```

### Таблица `parser_users`
Найденные пользователи:
```sql
- user_id: Telegram ID пользователя
- username: @username
- first_name: имя
- source_chat_id: ID чата где нашли
- source_chat_title: название чата
- has_gifts: есть ли у него подарки
- gifts_count: количество подарков
- checked_at: когда проверяли
```

### Таблица `parser_gifts`
Найденные подарки:
```sql
- user_id: кому принадлежит
- gift_id: ID типа подарка
- gift_name: название
- gift_slug: slug для ссылки
- gift_num: номер подарка
- can_upgrade: можно ли улучшить
- is_collectible: коллекционный ли (NFT)
- estimated_price: примерная цена в Stars
- found_at: когда нашли
```

## 🔐 Безопасность

### StringSession
- Это зашифрованная строка с данными авторизации
- Содержит токены доступа Telegram
- Храните в секрете! Не публикуйте!
- При утечке: отключите сессию в боте и создайте новую

### Access Hash
- Для каждого пользователя Telegram даёт уникальный access_hash
- Это требуется для проверки подарков
- Сохраняется при первом обнаружении пользователя
- Используется в `InputPeerUser(user_id, access_hash)`

## ⚡ Производительность

### Скорость парсинга

**Зависит от:**
- Количества участников в чатах
- Режима (💎 быстрее чем 🎁)
- Ограничений Telegram API
- Количества пользователей с NFT

**Примерная скорость:**
- Маленький чат (100 человек): 2-5 минут
- Средний чат (1000 человек): 15-30 минут  
- Большой чат (5000+ человек): 1-2 часа

### Почему медленно?

1. **API лимиты**: Telegram ограничивает запросы
2. **Паузы**: Между запросами обязательны паузы
3. **FloodWait**: При превышении лимитов Telegram блокирует на время
4. **Батчинг**: Данные загружаются порциями, не все сразу

## 🎓 Технические термины

### MTProto API
- Низкоуровневый протокол Telegram
- Позволяет делать всё что может обычный клиент
- Telethon - это Python библиотека для MTProto

### StringSession
- Сериализованная (превращённая в строку) сессия
- Можно сохранить и восстановить позже
- Не требует повторного ввода кода

### Access Hash
- Секретный хэш для доступа к данным пользователя
- Telegram даёт его при первом получении информации о юзере
- Нужен для последующих запросов

### FloodWait
- Защита Telegram от спама
- "Слишком много запросов, подожди N секунд"
- Автоматически обрабатывается в коде

**Всё это происходит автоматически, вам нужно только:**
- Подключить аккаунт один раз
- Выбрать чаты
